# Direction C representative athlete

Direction C Stage 3 expands the approved local athlete across the complete eight-activity Kick family. It remains a bounded renderer layer, not a character-library migration. The imported v42 Canvas game, procedural Three.js rigs for other actors, physics, scoring, learning, profiles, local storage, and offline packaging remain canonical.

The match-visual-coherence slice adds an explicit camera-relative orientation contract to every activity profile. Goalward attackers face positive field X, keepers face negative field X, and both Header Duel competitors face the incoming cross at negative field X. Header Duel clones the already-loaded v2 skeleton with Three.js `SkeletonUtils`; it does not request or decode a second athlete asset. The opponent receives a local contrast kit and the same `HeaderReady`, `HeaderContact`, and `Recovery` clip pipeline as the primary athlete. The procedural rig remains the load-failure, reduced-quality, and Canvas fallback.

The controlled athlete alone carries a compact repository-rendered KickLab orbit badge: a broken cyan ring, navy center, white K, orange accent, and short pointer. The sprite follows the primary skeleton head with a protected vertical gap above the head/ball contact zone. Its target size is 46 px on desktop, 40 px on tablet, and 34 px on narrow mobile. Normal play uses a restrained two-centimeter-equivalent bob; reduced motion holds it static. Role ownership follows the active Direction C target, including attacker-to-keeper changes in Penalty shootout, while the opponent skeleton is never eligible. Physics Vision, move-log replay, cinematic replay/celebration, Canvas, reduced-quality, WebGL-failure, inactive, and renderer-hidden states suppress the badge so it cannot imply control over a recorded or fallback actor.

## Activation and fallback

The athlete is default-off and loads only when the local QA/runtime flag `?renderer=direction-c` is present. One data table resolves a named athlete, camera, contact node, and animation phase for Free kick, Header duel, 1v1 Dribble, Passing, Combo attack, Goalkeeper, Penalty shootout, and Crossbar. There is no player-facing renderer chooser or athlete-dimensions panel. Classic Canvas, WebGL failure, `quality=low`, constrained-device, and absent-flag paths keep the existing renderer. Reduced motion keeps the athlete visible but freezes looping motion to bounded representative poses. The lifecycle pause owner freezes the local animation clock, and replay uses the existing recorded Kick snapshots and replay-speed value.

The only runtime asset request is the same-origin repository path `assets/3d/kicklab-direction-c-athlete/v2/kicklab-makehuman-athlete.glb`. The manifest forbids external URIs. No runtime telemetry, upload, cloud processing, likeness, or external request exists. Version 1 remains in the repository as the PR #26 comparison/reference asset; it is no longer selected by the Direction C runtime.

## Authored contract

- source: repository-owned Blender file and deterministic Blender Python generators, using only MPFB 2.0.18 bundled core plus the official MakeHuman system-pack CC0 sportsuit, shoes, short hair, low-poly eyes, and young African skin assets; the existing sportsuit faces are locally partitioned into a navy jersey, cyan shorts, and white knee-high socks, while the existing shoes remain orange soccer boots;
- shared animation contract: the original seven Direction C clips and three markers remain unchanged on MPFB's 53-bone `game_engine` rig; nine self-authored activity clips reuse that same skeleton and existing bone/marker contacts;
- clips: `Ready`, `RunUp`, `Plant`, `Strike`, `FollowThrough`, `Celebrate`, and `Recovery`;
- contact: `StrikeContact_R` reaches `BallContactTarget` at 0.4 seconds in `Strike`;
- plant: `PlantContact_L` stays fixed from late `Plant` through `Strike` and the opening `FollowThrough` pose;
- surface: 26,502 triangles, four local materials, one 256×256 embedded skin texture, zero glTF errors, and zero glTF warnings;
- visual target: an adult-proportioned, football-readable Direction C athlete with fitted training kit, short hair, and a clear plant/strike silhouette. It is a fictional local derivative, not a real-person likeness.

The procedural stadium is part of the same regression gate. Every activity camera must retain the textured and marked pitch, four dimensional stands including both end returns, four roof panels, twenty roof-truss beams, four animated boards, a four-surface depth net, and shadow-casting hemisphere/directional lighting. The crowd is a self-authored three-tier system. The nearest tier combines four bounded `SkeletonUtils` clones of the already-loaded Direction C v2 shared rig with simpler dimensional hero supporters; the rig-derived adults retain the production athlete's face, hair, hands, forearms, layered soccer kit, legs, feet, shadows, and bounded `Ready`/`HeaderReady`/`Celebrate` poses while using distinct fictional palettes. Twelve lower-cost instanced middle layers bridge those people into a single muted procedural far-fill tier; empty seat depth, rails, row spacing, scale falloff, and occlusion keep the grandstand volumetric instead of mosaic-like. Desktop draws at most four simpler heroes per camera-facing stand plus two shared-rig heroes, tablet three plus two, and narrow mobile two plus one. Distance LOD keeps one to three layers per stand on desktop/tablet and no more than two on narrow mobile. Reaction placards use bounded sanitized messages and the active fictional local-profile nickname. A goal/reaction jumbotron performs a separate 640×360 desktop or 384×216 mobile render of three additional fictional adult clones from that same local shared rig; it never magnifies the far-fill texture or loads another asset. Lifecycle pause and reduced motion freeze every crowd mixer and the shared crowd clock. The crowd adds no remote asset request, new binary payload, or duplicated geometry buffer and is audited below 250 KB of procedural geometry buffers and 2.5 MB of generated texture/render-target memory. The athlete may not be accepted against a flattened background.

Stage 3 validation is `npm run qa:multi-activity-athlete -- <local URL> <output directory>`. Its primary Human-QA URL has no forced `athletePhase`; the harness drives normal controls and asserts phase time plus root/joint motion across all eight activities at 1440×1000, 768×1024, and 390×844. It also proves active motion freezes under lifecycle pause and idle looping freezes under reduced motion. The MP4 is a genuine real-time browser recording; paired wide and athlete-close screenshots are supplements. These desktop/browser gates do not qualify a physical mobile device, native shell, signing, distribution, deployment, or store submission.

Focused Header Duel validation is `npm run qa:match-visual-coherence -- <local URL> <output directory> <revision>`. It records the canonical Space → 1180 ms → Space cadence and captures ready, live X-ray, and Recovery at desktop, tablet, and mobile widths. It also asserts orientation labels, controlled-player badge ownership and responsive sizing, X-ray/replay/cinematic suppression, the shared skinned opponent, crowd depth/LOD, viewport frame pacing, reduced-motion freezing, Canvas fallback, zero runtime egress, zero page errors, and zero horizontal overflow before encoding the desktop walkthrough as H.264 MP4.

Crowd-only validation is `npm run qa:crowd-fidelity -- <local URL> <output directory> <revision>`. It captures Free kick and Header duel ready, action, and reaction states at 1440×1000, 768×1024, and 390×844. In addition to the full responsive matrix, it records a same-frame Free-kick crop containing the field athlete and the closest shared-rig stand supporters at comparable displayed scale, desktop and mobile jumbotron-in-stadium context, tight close-up crops from the normal rendered reaction state, and a combined desktop/mobile H.264 walkthrough. The harness verifies shared-rig source, mesh and bone presence, hero/mid/far counts and LOD selection, jumbotron supporter count and resolution, nickname reaction signage, geometry/texture and built-payload guardrails, lifecycle pause, reduced motion, Canvas fallback, frame pacing, zero egress, page errors, and overflow. It does not modify the field, athlete, ball, goal, Physics Vision, HUD, controls, physics, scoring, or learning behavior.
