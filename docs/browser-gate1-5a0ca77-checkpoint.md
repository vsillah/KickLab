## Deterministic product defect found on `5a0ca77`

Race preflight cancellation loses keyboard focus when the 3D orbit is still settling. Under reduced motion, select Highland → Circuit and close preflight by its Close button or Escape. Once the orbit finishes, **Start heat is visible, Race remains on the grid, and the saved profile is unchanged, but `document.activeElement` is `BODY`**. The exact-build [repro script](../scripts/qa-race-preflight-cancel-focus.mjs) failed in all three bounded cases: 390 × 844 Close, 390 × 844 Escape, and 1440 × 900 Close. The [sanitized report](evidence/browser-gate1-5a0ca77-race-preflight-cancel-focus.json) records each state; the [390 × 844 screenshot](evidence/browser-gate1-5a0ca77-390-preflight-cancel-focus.png) confirms the visible Start heat target. No app external requests, page errors, or HTTP errors occurred. The in-app browser spot check without reduced motion returned focus to Start heat, so the failure is bound to this transition timing and needs a product fix and exact-head rerun.

These checks used browser emulation and synthetic local profiles. The older `b509fb9` visible-browser pacing table and screenshots were removed from this PR because they do not bind to the current artifact. The current deployed 20-case p95 result above is attributed to the Captain's PR #147 qualification, not to a new independent visible pacing run in this lane.
