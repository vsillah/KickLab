## Phase 3 work packages after separate authorization

1. **Exact baseline and isolated lanes.** Captain records approved main, 204-file package digest, lockfile hash, the current rights/notice state, and any source delta since this plan. Create separate named iOS and Android branches/worktrees. Run `npm ci`, `npm run check`, `npm run mobile:check`, and capture package/web/mobile hashes before native generation. Stop on any mismatch, new held hash or unapproved dependency change.
2. **Unsigned project generation.** With a separately approved toolchain and bounded changes, generate iOS and Android Capacitor projects from the same copied package. Verify iOS deployment target and Android min/compile/target SDK floors against the current pinned Capacitor version. Audit generated dependency and transitive notice inventory. Keep signing credentials and provider accounts out of the lanes.
3. **SDK, permission and data-flow audit.** Enumerate all native packages, entitlements, manifests, permissions, network endpoints, OS services, telemetry/crash paths, WebView bridges, clipboard/QR behavior and any off-device transfer. Record observed traffic while offline and online; fail on unexplained egress. Update the unpublished privacy/data-flow worksheet only from actual native behavior.
4. **Simulator and emulator qualification.** On named OS/runtime versions, test clean install, all three labs, progression/profile continuity, cold start, background/resume/interruption, held-input cancellation, orientation/safe areas, offline launch, local deletion, multi-profile/legacy migration, uninstall/reinstall and backup/restore behavior. Bind logs and playable, privacy-safe rendered evidence to exact binaries and copied package hashes.
5. **Physical-device and accessibility qualification.** On a defined phone/tablet matrix, test touch, audio/haptics, thermal/memory, lifecycle, offline, deletion and backup effects. Run VoiceOver/TalkBack, focus/names, dynamic text/zoom, contrast, reduced motion and canvas alternatives on exact builds. Record failures and rerun affected cases after fixes.
6. **Captain review.** Review isolated PRs, source/product diffs, dependency and notice changes, all test evidence and exact artifact identities. Do not call Gate 2/3/4 qualified from project generation or CI alone. Any new data path, permission, rights concern, package hash or user-facing change returns to a bounded decision and applicable Human QA gate.

**Phase 3 output:** unsigned, unuploaded local iOS/Android qualification artifacts and a pass/fail evidence matrix. Signing, TestFlight/Play internal distribution, store records, final declarations, policy publication and launch remain later separately authorized gates. This plan does not alter the [seven-gate native roadmap](mobile-qualification-roadmap.md).
